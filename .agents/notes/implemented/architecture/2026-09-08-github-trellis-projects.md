# GitHub Trellis project sources

GitHub projects use API blobs pinned to one resolved commit, while local projects keep filesystem discovery and the controlled archive coordinator. The shared task parser preserves status, phase and evidence semantics across both sources. Remote entries have no filesystem root and the Host rejects remote archive preparation; a missing button alone does not enforce read-only operation.

Selections live in a separate versioned file under the plugin data directory, keeping existing local path overrides and unrelated overlay state intact. Atomic replacement and serialized management prevent concurrent source changes from overwriting each other. Github API requests use fixed origins, no redirects, bounded bodies, abort signals and ordinary blob modes. Failed refreshes expose stale provenance and retain no disk cache of private task data.

Project source configuration belongs to the Personal content workbench plugin settings. The settings card receives the existing Trellis GitHub face so successful source changes use the same project revision notifications as other project operations. Local directory edits remain settings drafts until Save; source switching and GitHub actions apply immediately and are not reverted by Discard. The Projects sidebar owns browsing, search and refresh, while its global settings trigger remains available.

Device authorization belongs to an administrator-registered GitHub App with read-only repository permissions. No bundled third-party App identity, GitHub CLI credential reuse or token input is assumed. The DSH credential provider owns token storage; the browser receives only the user-facing device code. Authorization checks are explicit, respect provider intervals and stop after expiration. Unbinding clears credentials and cached project data; an authorization generation prevents an in-flight read from restoring data after unbinding.

Focused network-fixture tests cover commit-pinned parsing, malformed or unsupported source input, persisted selections, stale snapshots, tree limits, symlink rejection, device authorization intervals and secret exclusion. DOM tests exercise repository and branch selection with real shared UI controls. Live private-repository authorization requires an administrator-provided Client ID and user completion on GitHub; synthetic authorization tests do not establish that acceptance.
