# Muzi Creator Animal Island UI Lab

This Lab is an isolated visual and interaction harness for Muzi Creator. It supplies no credentials and authorizes no publishing, synchronization, or archive action.

## Visual system

Animal Island defaults remain scoped to Muzi roots and portals. The workbench bundles its fixed appearance, fonts and artwork, retaining host light/dark mode.

The package is `animal-island-ui@1.6.0`, licensed CC BY-NC 4.0 by guokaigdg. Muzi Creator code remains MIT; `NOTICE` is the attribution record.

Workspace header controls have transparent resting backgrounds, subtle hover fills, and visible keyboard focus. Host tooltips use a fixed cream background (`#FFF8EA`), brown text (`#694633`), and a faint brown border in both light and dark modes. These appearance rules apply only while the workbench client is active. Tooltip rules exclude plugin-owned surfaces and portals, with a scoped exception for host tooltips rendered inside the sidebar's `sidebar.workspaces` slot.

Feature-list toolbars align their title and 36 px actions on one 44 px row. Titles shrink and truncate before controls; expanded search occupies the same row. Feature-list toolbars omit item totals; overview metrics, list-group counts and activity badges retain their meaning. Content keeps search and view options. Knowledge shows the title “知识” and search. Neither toolbar offers creation or knowledge preview actions. Inspiration uses an icon-and-text Search control, named Search history for assistive technology, to reveal and focus its history filter; Escape or Clear resets the filter, closes it and restores trigger focus. Its toolbar contains only history search and refresh; research starts from the central workbench. Hotspot refresh uses the short Refresh label and the shared refresh icon.

## Component map

| Surface | Preferred component | Notes |
| --- | --- | --- |
| Content, knowledge, hot and project cards | `IslandSelectableCard` over `Card` | Provides `button`, `aria-pressed`, roving focus compatibility, and Enter/Space selection without restyling the library card. |
| Status, stage, file and source labels | `Tag` | Keep status meaning in text, not color alone. |
| Search, date-time and controlled text fields | `IslandInput` over `Input` | Controlled value and change handler are required. |
| Platform, account and mode choices | `Select` | Controlled `options`, `value`, and `onChange`; unavailable choices stay visible as explanatory text but are excluded from the focusable option list. |
| Enable/confirm choices | `Checkbox` / `Switch` | Preserve the external-action safety defaults. |
| Actions | `Button` | Primary depth shadow is reserved for primary/danger actions. |
| Loading | `Skeleton` / `Loading` | Do not replace meaningful error or unavailable states with an indefinite spinner. |
| Loading, error, empty and information messages | `IslandState` | Keeps live-region semantics and optional recovery actions consistent. |
| Details and confirmation | `Modal` / `Drawer` | Keep focus, cancellation, and one-time confirmation behavior. |
| Feature icons | `WorkbenchIcon` | Bundled PNGs for navigation, feature headings and matching actions, with SVG fallbacks. Platform identities and directional controls retain their own symbols. See [icon placement](docs/iconography.md). |
| Multiline editor | `IslandTextarea` | Controlled native textarea exception with a shared theme, label and focus treatment. |
| Plugin settings card header | DSH disclosure chrome | The settings-list shell mirrors the official 2.0.4 plugin card, including its host tokens and chevron; the disclosed business form continues to use `IslandControls`. |

`IslandInput` preserves native `datetime-local` editing inside the shared shell. The controlled textarea inside `IslandTextarea` and the 3D graph canvas remain because the library has no behavior-equivalent component. The graph retains its keyboard fallback; date and textarea fields retain labels, focus visibility and DOM coverage. No other raw form control is part of the plugin UI.

## Layout and responsive constraints

Feature navigation uses `aria-selected` for its persistent highlight: the selected entry keeps the theme accent background and matching ink through hover and press, without an action-button shadow or vertical movement. These rules apply only to the Muzi sidebar; other plugin buttons keep their own presentation.

Sidebar navigation labels use a 1.5 line height and vertical insets to keep Chinese glyphs clear of their truncation box. All Muzi text inputs, date-time inputs, textareas and Select triggers share a 2 px inset focus outline; input shells own the outline and native inner fields have none. Stable adapter classes scope these rules to Muzi controls, including modal controls. Error and warning inputs retain their semantic outline color; disabled controls retain their disabled state. Text, placeholders and surfaces follow the active theme. Central toolbar and content-tab backgrounds share a warm parchment token in light mode and the secondary surface in dark mode, with explicit tab text colors.

The host-provided sidebar width is authoritative: 360 px is the primary expanded design width and 56 px is the settled rail. The central `conversation` region has two explicit modes. Selecting Sessions unregisters the Muzi occupant and restores the complete official Agent tree. Selecting Hot, Inspiration, Content, Knowledge or Projects registers one stable Muzi workbench root at priority `-10`; switching between those five features updates that root without re-registering it. Activating a feature navigation entry, including the active entry and keyboard navigation, clears only its detail selection and opens its overview. Refresh restoration and direct account-management links retain their existing behavior. Business details are ordinary central views and do not use `shell.overlay`, fixed positioning, resizable widths, masks or close layers.

The workbench preserves the pre-split navigation: a leading icon, a label centered against the complete row, and a trailing Sessions activity badge. Workspace header controls remain host-owned and retain their existing search, view and add-workspace behavior.

The central root has one top bar and one independently scrolling content region. Overview content is limited to 1120 px, reading content to about 72 characters, and the knowledge graph uses the available width. Below 880 px, only a new item selection asks the official layout action to collapse the sidebar; opening an overview, refreshing, changing features or restoring an existing selection does not. The expanded-list action and overview return restore keyboard focus to the source row. At 620/560/430 px internal layouts stack or reduce padding without page-level horizontal overflow. The graph canvas keeps its keyboard fallback and loading, empty, unavailable and reduced-motion states. The Inspiration selected tab shares the sidebar accent background and matching text in both themes. The Inspiration workbench has two compact tabs: topic search and date-limited hotspots. Each form exposes only a topic, the hotspot time range when relevant, and its submit action. The sidebar owns one chronological history list. Results show an expanded summary, numbered findings, disagreements with recorded evidence labels, creative angles and sources; copy, search again, session, Obsidian and content actions remain directly visible. Searches continue in their dedicated Agent sessions while another feature is open.

Tabs remain one line, scroll horizontally, and use the library keyboard behavior for Arrow keys, Home and End. Long Chinese or English titles, URLs, source labels and Windows paths either wrap at safe boundaries or truncate inside a `min-width: 0` container. Card delete controls sit at the right edge, vertically centered against the full card, with reserved text space. Content overview production and publication action buttons contain text only. Card shadows are not added by plugin CSS; depth remains owned by Animal Island primary or danger actions.

Knowledge list cards are text-first: their 14 px by 16 px inset and natural content height leave the full width for a left-aligned title, topic tag and two-line summary. Individual cards contain no decorative icon or reserved icon slot; the top-level Knowledge navigation uses the generated open-book icon.

Trellis project details keep the four task groups at an equal height. Each group places every filtered task in a 264 px internal scroll region that shows exactly five 48 px rows separated by four 6 px gaps; shorter groups retain the same space and center their empty state. Overflow remains inside the group, selected tasks can be brought into view, and changing the project or priority returns the task regions to their starting position. The task list has no preview disclosure, floating layer, native select or persisted scroll position.

The video-production view includes an optional local project path, save/unlink actions and an action that opens only its containing folder. Export waiting works independently of project binding; stopping the wait never stops the external editor. Paths wrap on narrow screens, in-flight operations prevent duplicate writes, and failed actions preserve the input for retry.

Content detail tabs join the detail body edge to edge, with one bottom divider and no outer margin, rounded shell or shadow. The body has 24 px padding, reduced to 16 px below a 620 px container width. Content overview uses a compact cover, title, stage and update-time row above three sibling sections: production, documents and publication. At container widths of 880 px and above their columns have a 1:1:1.2 ratio and 16 px gaps; from 620 px to 879 px production spans both columns, and below 620 px all sections stack in reading order. Each section uses a thin border and a colored heading band: sage for production, apricot for documents and mint for publication, with corresponding dark-theme colors and solid icon backplates. Document and publication rows have a 48 px minimum height; metadata and task warnings wrap below their primary status row. Sections use the shared body scroll area. Publication management expands full-width below the sections. Production shows its current stage and next action; detailed checks stay in Video production. Publication facts retain their own status, time and link, while the current publishing task appears separately. A scheduled platform draft is not a published work; an unknown submission result requires verification. Blog rows describe article publication.

Account management fills the central workbench with its own vertical scroll area and 24 px padding, reduced to 16 px below a 640 px workbench width. The heading and paper list share their edges. Account identity takes the remaining row width; verification time and actions keep their natural widths. Publishing management is initially collapsed and keeps its form state and operations when hidden. Selecting another content item closes it. Inspiration details fill the available pane width with balanced side insets. ## Theme and portal boundary

The client effect owns the appearance marker, styles and entry adapters. Disposal releases them without changing persistent host theme values.

Appearance rules live in src/client/appearance. Desktop 2.0.5 compatibility uses semantic entry markers and dedicated marketplace anchors.

Plugin roots carry data-plugin="dsh-muzi-creator" and body portals carry data-plugin-modal="dsh-muzi-creator". The owned layout stylesheet retains the sidebar workspace toolbar and narrow-window positioning in light and dark modes. It does not replace host controls, accessible names, events or plugin visibility.

## Desktop 2.0.4 acceptance boundary

The Desktop path is pinned to Windows x64 DSH Desktop 2.0.4 and its bundled Harness 0.1.2-alpha.1. `.lab/desktop-home` owns the isolated DSH Profile; `.lab/desktop-user-data` owns Electron state. Both isolated homes provide ordinary writable `Desktop`, `Documents` and `Downloads` directories because the host directory picker does not accept an initial location. Settings directory selection calls the composed `workspaces.pickDirectory()` service; its native or browse flow is supplied by DSH's directory-picker package, so Web Lab and Desktop use the same client contract. The generated `profile-selection/state.json` is exactly `{ "version": 2, "active": "web" }`; `desktop-market/state.json` explicitly requests `disabled`; `settings.yaml` explicitly sets `dsh-desktop.mode: compatibility`. Desktop launch is fail-closed when the executable identity, any generated profile file, source link, writable directory, selection state or required `lib/` artifact differs. Desktop 2.0.4 rejects the former version-1 state and otherwise recovers to its launcher-owned `desktop` Profile, so the Lab validator rejects that legacy document before launch.

The opt-in personal mode keeps `.lab/personal/dsh-home`, `.lab/personal/user-data` and `.lab/personal/data` separate from both the fixture Lab and the user's formal DSH state. It preserves the process's real `HOME` and `USERPROFILE` only for native shell discovery, while `DSH_HOME`, application-data variables, credentials, telemetry and external-action policy remain isolated. Its generated profile points to the validated local Creator Studio, Atlas, Trellis and Obsidian paths. Configuration files are create-once: identical regeneration is allowed, but a conflicting personal config, profile or overlay is never overwritten silently. These business roots are real rather than sandbox fixtures, so validation is read-only and deliberately avoids content creation, organization, archive, synchronization, publication and Atlas writes.

On 2026-09-02 the source-linked plugin was verified with Desktop 2.0.4's packaged Harness in the isolated `web` Profile. The native Electron walkthrough confirmed compatibility mode, central overview replacement for hot/content/knowledge/projects, official Agent restoration for sessions, hotspot detail restoration across feature switches, and hotspot detail restoration after a full Desktop restart. The same build passed light/dark Web Lab checks at 1440×900, 1280×800, 1024×768, 879×800 and 390×844 without page-level horizontal overflow. The isolated fixture intentionally leaves Atlas and Trellis unavailable, so their empty/error states were verified without writes. Inspiration research execution against live web sources and local report generation remain `UNVERIFIED` Desktop checks; unit and DOM tests cover the bounded ledger paths. Local `.tgz` installation remains a separate `UNVERIFIED` packaging check; a downloaded installer with the expected SHA-256 proves artifact identity only.

## Host integration boundary

DSH continues to own session state, the official Agent tree, settings host, approvals, composer, details column and shell layout. Muzi Creator conditionally occupies only the root `conversation` slot for Hot, Inspiration, Content, Knowledge and Projects. Selecting Sessions disposes that registration so the official component tree, active session, draft, queue and stream return unchanged. Muzi never registers `conversation.view`, `conversation.composer.bar` or `sidebar.settings`; the official details region and global portals remain intact. A failed root registration leaves the official conversation visible and reports the failure in the Muzi sidebar instead of using DOM selectors or hiding host components.

The five business features share one read controller per source. First open loads once, concurrent sidebar and overview requests are coalesced, manual refresh retains the last valid value, and one source failure stays local to that feature. UI schema 3 stores independent Hot, Inspiration, Content, Knowledge and Project selections under `dsh-muzi-creator/ui/v3`; v2 state is migrated without clearing the other selections, and every restored identity is checked through its existing Face before detail rendering. Manual inspiration runs use a durable Host ledger, a single concurrent bounded Agent, and immutable Markdown reports under `00-inbox/inspirations`; reports remain unread until opened. Legacy daily plans are paused before runtime attachment and cannot be re-enabled. Relative hotspot windows resolve per request; custom dates include both selected days in Asia/Shanghai. Old reports remain readable without invented time windows. The Sessions badge reads only official session summaries and prioritizes pending interactions over running counts. None of these paths sends, stops, cancels, approves or switches an existing session.

Host compatibility CSS is presentation-only and cannot add handlers or change disabled state.

The plugin owns its business surfaces under `data-plugin="dsh-muzi-creator"` and its own CSS files. The injected Hero mark carries the same ownership attribute. The Lab creates disposable Web and Desktop profiles under `.lab/`, links only the current source checkout into those profiles, and never copies a real DSH profile, credentials, or user content. Every Lab start verifies the generated manifest, patch, workspace file, confined writable paths, checkout link and built artifacts before launching DSH.

Inspiration history and content cards expose a separate delete button beside the selectable card. Confirmation removes the record from workbench lists while retaining local folders, manuscripts, reports and sessions. Research runs cannot be removed while queued or running. Deletion persists across restarts and uses revision checks; a failed request keeps the card and shows its error. The action is a sibling of the card selection control so mouse and keyboard deletion do not select the card.

Card deletion uses the theme-aware native IslandModal. The dialog shows the card title and retained-file explanation, focuses Cancel first and restores the trigger after cancellation. Parents can veto Escape, backdrop and close-button dismissal while deletion is pending. Failures stay inside the dialog for retry; long titles wrap within viewport bounds.

The workbench header reserves an 88 px end inset for the host details toggle. In narrow central panes, title and actions use separate rows. Inspiration report actions share one wrapping row, a 36 px button height and 8 px gaps; all use the same outlined control style, with a divider above the action row.

Project sources live in Settings → Plugins → Personal content workbench, alongside the local project folder. The Projects sidebar retains browsing, search and refresh, with the global settings trigger at the bottom. Local folder changes use the settings Save and Discard actions; source switching and GitHub operations apply immediately, as explained in the section. The source selector shows only the selected source configuration: local folder settings or GitHub repository and authorization controls. Switching preserves drafts and waits for the saved source mode before changing the visible fields. The GitHub form accepts a public repository URL or username, then lets the user choose a repository and branch before adding it. It uses shared Animal Island Input, Select and Button controls; the scoped listbox stays position-static and opens downward so the scrolling settings panel does not clip it. When the app connection is unavailable, its button is disabled with an explanation. Remote details show branch, commit, sync time, stale state and read-only status; removing a source removes only the connection.

Card margins follow the inspector container width: 24 px from 880 px, 16 px from 621 to 879 px, and 12 px below that. The tab strip has a 16 px inset (12 px through 620 px); body padding is 24 px (16 px through 620 px). The library panel adds no second padding. Tabs remain fixed above the independently scrolling body, and the overview sections remain grouped without additional card shells.
